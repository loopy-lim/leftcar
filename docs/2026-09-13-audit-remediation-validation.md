## 실제 성능 수치의 해석

동일 실행 안에서 원본 068과 후보의 순수 정책을 비교했다. 불가능한 FEC 복원 100회는 400회 할당/448800 요청 바이트에서 0/0으로 줄었다. 1268개 RTX 봉투의 논리 보관량은 양쪽 1775200바이트이며, 보관·조회 시간은 380031ns에서 561081ns로 늘었다. 1600개 과대 AU는 원본 2240000바이트 보관에서 후보의 전체 AU 거부/0바이트로 바뀌었다. 이 결과는 해당 경로의 할당·정책 비용이며 RSS·실기기 FPS·배터리 개선율이 아니다.

Sunshine·Moonlight·scrcpy 비교는 고정 소스의 구조 분석이다. 경쟁 제품을 같은 기기에서 실행해 순위를 측정한 결과가 아니다. 태블릿 조작 준비에 사용한 scrcpy는 측정 시작 전에 종료한다.

## 실기기 상태와 미검증 범위

TB710FU의 일반 앱과 분리된 baseline·후보 Viewer를 설치·실행하고 각각 테스트 Host와 페어링했다. 최신 후보 APK의 설치 바이트는 빌드와 일치한다. 이전 APK의 수동·빠른 연결 실패 뒤 잘못된 연결됨 표시를 재현한 후, 최신 APK에서는 오류와 연결 안 됨이 함께 표시됨을 확인했다. 주소 입력에 포커스가 있는 첫 탭이 연결 시도를 시작했지만 소프트 키보드는 표시되지 않아 키보드가 열린 조건은 미검증이다.

처음 전용 Display 1 승인을 시도했을 때 자동 승인 검토가 정확한 화면 공유의 명시적 승인을 요구했다. 이후 사용자가 전용 화면 ‘Leftcar Audit 20260913 S1’과 2개 로컬 커밋을 승인했다. 20:45 KST 이후 실제 Host UI에서 개인 화면 Display 0을 끄고 Display 1만 선택·승인했다. Host의 ‘화면 접근: 1’과 Viewer 목록의 Display 1 단독 표시를 확인했다. 권한 파일은 직접 수정하지 않았다.

최신 Host를 20:41:59 KST에 별도 프로필로 실행했다. 이름·UUID·2560×1440/60Hz·scale1인 전용 화면을 다시 확인했으며 시스템 오디오는 캡처 전부터 꺼지는 벤치마크 정책을 유지하고 Viewer 오디오도 껐다. 원격 입력을 켜는 동작은 하지 않았다. 직접 Wi-Fi 주소는 실제 Viewer에서 시간 초과가 났다. 별도 공개 연결 응답 검사에서도 루프백은 2ms에 응답했지만 같은 컴퓨터의 LAN 주소는 3004ms 후 시간 초과였다. 정적 TCP 검사에서도 재현된 증상이며 정확한 OS·네트워크 원인은 미확정이다. 네트워크 설정은 바꾸지 않았다.

ADB의 후보 전용 제어 연결은 성공했다. 그러나 이 ADB 자체는 Wi-Fi 연결이며 USB가 아니다. 20:48 KST에 전용 화면의 합성 스크롤 소스를 띄우고 Viewer에서 Display 1을 열었으나 `UDP reachability proof failed for 127.0.0.1:5001`로 중단됐다. 제어용 루프백 주소는 태블릿의 UDP 영상 수신 주소를 제공하지 못한다. 실제 영상은 열리지 않았고 FPS·지연·연속 재생 통과 기록도 없다. 합성 소스가 표시된 70.219초는 영상 측정 시간이 아니다.

20:49:34 KST까지 테스트 Host를 정상 종료하고 종료가 확인된 뒤 합성 화면을 닫았다. 임시 태블릿 조작 도구와 이 작업이 만든 제어 매핑 `tcp44711 → tcp50744`도 제거했다. 기존 `tcp8877` 연결과 일반 Host는 유지했다. 준비된 가상 화면과 격리 앱은 후속 검사를 위해 보존한다. 이전 10.002428초 유휴 수집 검사는 정상 macOS 안내 문구 처리와 프로세스·시계·자원 수집에 대한 근거이며, 영상 통계가 없어 실패로 판정한 기록이다.

짧은 반복 → 10분 → 30분의 성공한 실제 영상 측정이 남았다. 전용 화면 승인 조건은 해결됐고 실제 미디어 전송 경로가 필요하다. 앞서 데이터 USB 연결 가능 여부를 요청했으나 이후 사용자가 실기기 검사를 추후 직접 진행하기로 했다. 구형 baseline의 자동 입력 활성화도 후보의 입력 꺼짐과 동일하다고 간주할 수 없다. baseline·후보의 연결 방식, 입력 상태와 실제 출력 조건을 각각 기록해야 한다. 충전 중 배터리로 소비 전력을 비교하지 않으며 물리 패널 3200×2000과 4K 인코딩 입력을 구분한다.

AOAP의 즉시 정지·재시작 시 이전 proxy 종료를 기다리지 않는 기존 경계는 승인된 수정 범위 밖의 후속 항목으로 남는다. 기기 재연결 검사에서 확인하고 별도 수정이 필요하다.

Surface 해제 시각은 물리 표시 시각이 아니다. Windows 실제 실행·설치 파일, Android API24 기기, OEM별 동시 디코더, 실제 오디오 재생·A/V 차이, 광학 glass-to-glass와 공개 서명은 해당 증거가 없으면 미검증으로 남는다. 앞선 결과는 구현·검증 문서 2개 로컬 커밋으로 보존했다. 이후 사용자가 simplify와 푸시·PR 머지를 승인하고 실기기 검사를 추후 직접 수행하기로 했다. PR 통합은 공개 서명 릴리스나 실기기 수용을 뜻하지 않는다. 전체 스테이징 공백 검사에는 패치의 빈 문맥 줄 11곳과 Swift 파일 끝 빈 줄 2곳이 표시됐다. 전자는 패치 형식이고 후자는 동작 영향 없는 서식이다. 그 시점에는 검증된 바이트를 유지했고 후속 simplify에서 Swift 끝 빈 줄 2곳을 정리했다. 패치 문맥 공백은 형식상 유지한다. 새 파일을 보지 않았던 이전 `git diff --check` 결과를 전체 공백 무결성으로 해석하지 않는다.
