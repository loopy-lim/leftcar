# 화면 확장 사용성 개선

사용자 목표: LAN/외부 화면 공유의 안정성을 유지하면서 연결·종료·재연결, 배치·크기, 마우스·키보드·터치를 모두 점검하고 개선한다. 2026-09-22 답변으로 세 영역 모두 우선순위임을 확인했다.

## 비교 기준과 현황

[Apple Sidecar 안내](https://support.apple.com/en-au/102597) 및 [iPad 사용 설명서](https://support.apple.com/guide/ipad/use-your-ipad-as-a-second-display-ipad2b1aa3be/ipados)를 기준으로 점검했다. Sidecar는 기기 선택으로 확장을 시작하고 디스플레이 배치를 조정하며, Mac 입력과 태블릿 보조 입력을 사용하고 양쪽에서 종료한다.

| 영역 | 현재 코드에서 확인한 상태 | 개선/검증 |
|---|---|---|
| 시작 | 뷰어 생성 후 자동 열기 존재. 기존 화면이 있으면 제거가 주 동작 | 기존 확장 화면 열기를 주 동작으로 제공 |
| 지원 감지 | 뷰어 생성 버튼이 모든 호스트에 표시 | 호스트 capability와 권한을 반영 |
| 자동 크기 | 패널 메트릭 도출 존재. Host UI가 추천을 프리셋에서만 찾아 임의 비율은 무반응 | 값 기반 선택과 명시적 적용, 자동/프리셋/직접 입력 |
| 크기 변경 | 스트림 해상도와 macOS 작업 공간 크기가 혼재 | 화면 크기 설정과 전송 품질을 구분, 명시적 재생성 |
| 제거 | 최대 90초 고정 pending, 재생성 중복 위험, Host UI 갱신 없음 | 실제 소실 기준 pending, 작업 직렬화, 상태 갱신 |
| 배치 | private bridge에 좌표 이동만 있고 사용자 조작 없음 | 화면의 왼쪽/오른쪽/위/아래 배치, 기존 화면/primary 보존 |
| 입력 | 시작 시 저장한 display bounds와 커서 정규화 bounds가 고정 | 현재 캡처 디스플레이의 좌표를 다시 반영; 끝점이 옆 화면으로 벗어나지 않음 |
| 재연결 | 동일 source UUID, 자동 호스트 재연결, 수동 stop 게이트 존재 | 재사용/호스트 선택 변경/제거 중 경합 회귀 검증 |
| 키보드·터치 | 신뢰 기기 입력, release-all, 한영 전환, 스타일러스 압력 경로 존재 | 기존 회귀 테스트와 새 배치 입력 확인 |
| 잠자기/실기 품질 | 과거 자료의 미검증 영역 존재 | 현재 후보의 증거만 보고, 실기와 자동 검증을 분리 |

## 설계

기존 CGVirtualDisplay → 카탈로그 → 캡처/전송/입력 경로를 유지한다. 확장 화면 하나의 수명은 Mac이 소유한다. 단순 스트림 닫기나 네트워크 단절로 작업 공간을 삭제하지 않으며, 화면 제거는 명시적인 동작이다. 안정된 UUID와 macOS 배치 기억을 활용한다.

상태 조회는 지원 여부, 현재 source와 논리/실제 크기, 제거 진행을 제공한다. 제거가 실제 완료되기 전 동일 identity 생성은 차단한다. 크기 변경은 제거 후 재생성한다. 배치는 현재 모드를 그대로 지정하는 원자적 설정으로 Retina 좌표를 유지한다. 다른 기기의 사용 중인 화면을 임의로 재구성하지 않는다. 인증·화면 승인 확인 후 원격 관리 명령을 처리하고, 기존 화면에 대한 승인 확장이 다른 스트림을 끊지 않는지 점검한다.

Host와 Viewer에서 ‘열기’를 기본으로, 배치 및 크기 설정을 보조 동작으로 제공한다. 자동 모드는 최근 패널 메트릭을 사용하고, 직접 입력은 논리 픽셀과 Retina 배율을 구분한다. UI는 선택만으로 생성/삭제하지 않으며 명시적 버튼을 사용한다. 비동기 작업은 호스트 선택과 컴포넌트 수명에 묶어 늦은 응답이 다른 Mac의 화면을 여는 것을 방지한다.

## 검증과 범위

실제 UI 컴포넌트 회귀, Rust 상태/권한 테스트, Swift 입력·커서 및 native display lifecycle 검증을 수행한다. React 변경 후 저장소 규칙에 따라 React Doctor 100/100, typecheck, 관련 테스트를 재실행한다. 빌드/자동 테스트, Mac 실기, 태블릿 입력/영상, 장시간 품질을 각각 기록한다.

Apple 전용 Touch Bar/Apple Pencil API와 Control Center 시스템 통합은 호환 기능으로 가장하지 않는다. 기존 Android 입력·설정 기능으로 대응 가능한 부분을 확인한다. 공개 배포/push는 포함하지 않는다. 커밋은 검증 후 파일·메시지를 제시하고 저장소 지침의 승인을 따른다.
