# 태블릿 화면 확장 실기 검증 절차

검토일: 2026-09-04
상태: 절차 확정 · 수행 대기
관련: docs/plans/2026-09-03-tablet-display-extension-design.md (검증·테스트 전략), docs/usb-physical-validation.md (E등급 정의·T11 절차), docs/EVIDENCE.md (결과 기록), docs/dev-environment.md (자동화 셸·클램쉘 세션 제약), docs/research/2026-09-03_cgvd-spark-results.md (활성 화면 전제 실측)

## 목적

태블릿 화면 확장(가상 디스플레이 생성 → 덮개 닫힘 "유일 화면 모드")은 현재 단위 테스트(E3)까지만 존재한다. 이 문서는 설계의 실기 검증 5항목을 재현 가능한 절차로 고정하고, 결과 기록 형식과 실패 시 진단 가이드를 정의한다. 수행 결과는 docs/EVIDENCE.md에 등급과 함께 기록하며, 이 문서의 절차를 그대로 인용해 재현할 수 있어야 한다.

실행 주체는 **사람(GUI 터미널에서 직접)** 이다. 자동화 셸은 GUI 로그인 세션 밖이라 디스플레이 생성·창 조작·스크린샷을 할 수 없다(docs/dev-environment.md). 덮개가 닫힌 채 화면 공유(Screen Sharing)만으로 원격 사용 중이면 활성 화면이 0개라 가상 디스플레이 생성 자체가 막힌다 — "먼저 만들고 닫는다"가 이 기능의 전제다(docs/research/2026-09-03_cgvd-spark-results.md).

결과 판정은 docs/usb-physical-validation.md의 E등급 정의를 **인용**한다(이 문서에서 재정의하지 않는다). 각 검증이 무엇을 달성시키는지만 밝힌다:

- **E3 (빌드/패키지)** — 현재 상태. `cargo test` 단위 테스트(Rust 82개, TS 195개)와 CI까지만 달성.
- **E6 (실제 호스트와 실기기 종단간)** — 검증 1–3이 통과하면 가상 디스플레이 경로의 E6다. 생성한 가상 디스플레이의 실제 픽셀이 캡처에서 전송을 거쳐 태블릿 표시까지, 그리고 터치 입력이 역방향으로 반영될 때 달성한다.
- **E7 (계측된 장시간 실험)** — 검증 4의 10분 생존은 덮개 닫힘 생존 계측의 최소 증거다. E7 판정 자체는 docs/usb-physical-validation.md 검증 4의 60분 soak 기준을 그대로 따르며 이 문서가 대체하지 않는다.

단위 테스트 통과와 가상 디스플레이 생성 성공만으로는 E6 증거가 아니다. 태블릿 화면에 실제 픽셀이 렌더되고 조작이 반영돼야 한다.

## 사전 조건 체크리스트

- [ ] BetterDisplay 4.3.6+ 설치, 실행 중, 설정에서 CLI 접근 허용 (T11 검증 6 실측 환경과 동일: 4.3.6 빌드 50119)
- [ ] 태블릿 + 데이터 케이블 연결, T11 검증 1(AOAP 핸드셰이크) 통과 상태
- [ ] 외장 USB 키보드·마우스 연결 (덮개 닫힘 후 유일한 입력 수단이 된다)
- [ ] AC 전원 연결 — 배터리에서는 세션 시작 시 `caffeinate`가 `-i`(절전 방지)로 강등돼 덮개 닫힘 생존이 불안정해질 수 있다. 배터리 상태는 결과 표에 반드시 기록한다.
- [ ] 덮개 열림 + 활성 화면 1개 이상. 덮개 닫힘·모니터 전원 꺼짐 상태에서는 시작이 "활성 화면이 없습니다"로 실패한다(by-design NoActiveDisplay — 실패 시 진단 가이드 1번).
- [ ] Host 앱에서 가상 디스플레이 (실험) 토글을 켜 카드를 표시한 상태 (토글 문구: "태블릿 화면 확장 (실험)")
- [ ] Host 빌드 커밋 SHA, BetterDisplay 버전, macOS 버전, 태블릿 모델 기록

이 문서의 절차는 기본 프로바이더(BetterDisplay CLI) 기준이다. CGVirtualDisplay shim(`tools/cgvd-shim/`)은 R-015 실험으로 본 절차 대상이 아니며, 별도 스파크 절차(`tools/cgvd-spark/run-probe.zsh`)에서 다룬다.

## 사전 확인 A: 앱 실행 경로와 betterdisplaycli 도달성

목표: Finder/Dock 실행처럼 최소 PATH로 뜨는 비대화형 환경에서도 `betterdisplaycli`가 도달 가능한지, 실패가 암호적인 오류가 아니라 안내 문구로 판별되는지 시작 전에 확인한다. Dock 실행 프로세스는 최소 PATH를 받기 때문에 PATH에 없는 CLI를 못 찾을 수 있다.

절차:

1. Host 앱을 Dock(또는 Finder)에서 실행한다. 자동화 셸·SSH 세션에서 실행한 결과는 무효다.
2. 가상 디스플레이 (실험) 토글을 켜고 카드가 나타나는지 확인한다.
3. "화면 확장 시작"을 누른다. BetterDisplay가 실행 중이면 세션이 시작된다(이후 검증 1로 진행). 시작에 실패하면 실패 문구를 그대로 기록한다.
4. 카드에는 상시 힌트 "BetterDisplay가 필요합니다. 설치 후 CLI 접근을 허용하세요."가 표시된다. 엔진을 못 찾은 경우의 실패 문구("가상 디스플레이 엔진을 사용할 수 없습니다: …" 형태의 ProviderError 안내)도 이 힌트와 함께 사용자가 따라갈 수 있는지 판정한다. 영문 raw 출력·무반응·크래시는 암호적 실패로 기록한다.
5. 앱을 어떻게 실행했는지(Dock / Finder / 터미널 `open` / GUI 터미널 직접 실행) 결과 표에 기록한다.

기록 항목:

| 항목 | 예상값 |
| --- | --- |
| 실행 경로 | Dock / Finder / 터미널 중 무엇이었는지 |
| "화면 확장 시작" 결과 | 세션 시작 또는 안내 문구로 판별되는 실패 |
| `which betterdisplaycli` (GUI 터미널 참고용) | 경로 출력 또는 없음 |

합격 기준: 시작이 성공하거나, 실패라면 "BetterDisplay가 필요합니다…" 힌트와 엔진 사용 불가 안내로 원인이 판별된다. 암호적 오류(무반응, 영문 raw 출력, 크래시)면 Fail — 실패 시 진단 가이드 2번으로 진행한다.

## 검증 1: 확장 모니터 — VD 생성과 태블릿 렌더

목표: 덮개 열림 상태에서 앱 카드만으로 가상 디스플레이를 만들고, 태블릿에 실제 픽셀이 렌더되며, 조작이 가능함을 확인한다. T11 검증 6의 잔여 항목(앱 UI 경유 생성 + 캡처 스트리밍)을 소거한다.

절차:

1. 덮개가 열려 있고 활성 화면이 1개 이상인지 확인한다: `ioreg -r -k AppleClamshellState | grep ClamshellState` → `No`.
2. 태블릿을 데이터 케이블로 연결하고 Viewer에서 Host에 연결한다.
3. 카드에서 이름을 확인한다(기본 `Leftcar Virtual`, 해상도 1920x1200 고정) — 이름은 편집 가능하다.
4. "화면 확장 시작"을 누른다. "태블릿 화면 세션이 시작되었습니다. 덮개를 닫아도 유지됩니다." 문구와 상태 pill(스트리밍 중)을 확인한다.
5. `system_profiler SPDisplaysDataType`에서 가상 디스플레이가 열거되는지 확인하고 명칭·해상도를 기록한다(또는 시스템 설정 > 디스플레이).
6. Viewer(태블릿)에서 카탈로그의 가상 디스플레이를 열어 스트리밍을 시작하고, 검은 화면이 아닌 실제 픽셀이 렌더되는지 확인한다.
7. Mac에서 마우스 커서를 가상 디스플레이 영역으로 이동시키고, 태블릿 화면에 커서가 반영되는지 확인한다.

기록 항목:

| 항목 | 예상값 |
| --- | --- |
| 세션 시작 | "태블릿 화면 세션 시작됨", pill 스트리밍 중 |
| `system_profiler` 열거 | `Leftcar Virtual` 1920x1200 |
| 태블릿 렌더 | 검은 화면 아닌 실시간 갱신 |
| 커서 반영 | VD 위 커서 이동이 태블릿에 표시 |

합격 기준: 가상 디스플레이가 생성되고, 태블릿에 실제 픽셀이 렌더되며, 마우스 조작이 태블릿 화면에 반영된다. 이것이 충족되면 가상 디스플레이 경로의 표시 절반(E6 전제)이 달성된다.

## 검증 2: 유일 화면 모드 — 덮개 닫힘 생존

목표: 덮개를 닫아 내장 패널이 꺼져도 가상 디스플레이가 외부 출력으로 생존하고 스트리밍이 지속되며, 외장 USB 키보드·마우스 입력이 태블릿 화면에 반영됨을 확인한다. 추가로 두 가지 수명 관찰을 함께 기록한다: B(앱 종료 시 VD 정리), C(반복 생성·제거 누적).

절차:

1. 검증 1을 통과한 상태(스트리밍 중)를 유지하고 AC 전원 연결을 확인한다.
2. `ioreg -r -k AppleClamshellState | grep ClamshellState` 사전값(`No`)을 기록한다.
3. 덮개를 닫는다. 내장 패널이 꺼져도 태블릿 화면이 계속 갱신되는지 확인한다.
4. 덮개 닫힘 직후 `ioreg -r -k AppleClamshellState | grep ClamshellState` → `Yes`를 기록하고, `system_profiler SPDisplaysDataType`로 가상 디스플레이 생존을 확인한다.
5. 외장 USB 키보드로 타이핑(예: 열려 있는 편집기·Spotlight 검색어)하고 태블릿 화면에 반영되는지 확인한다. USB 마우스 이동·클릭도 반영되는지 확인한다.
6. 카드 상태 pill 표기를 기록한다. 세션 실행 중 카드는 5초마다 상태를 갱신하며, 스트리밍 중 덮개가 닫히면 ioreg 판독에서 `clamshell`(유일 화면 모드)로 표기가 유도된다(표기용 — 덮개 감지는 UI 표시 목적이며 동작 판정은 4–5단계의 실측으로 한다). ioreg를 못 읽으면 표기는 `streaming`에 머문다.
7. **(B — 앱 종료 시 VD 정리 관찰)** 세션이 실행 중인 상태에서 외장 키보드로 Cmd+Q로 Host 앱을 종료한다. Drop 정리로 가상 디스플레이가 사라지는지, BetterDisplay가 이를 유지하는지 관찰하고 `system_profiler SPDisplaysDataType`으로 재확인한다. 앱 종료로 활성 화면이 0이 될 수 있으므로 관찰 직후 덮개를 다시 열어 복구한다.
8. **(C — 반복 생성·제거 누적)** 앱을 다시 실행하고 "화면 확장 시작" → "중지"를 5회 반복한다. 매 중지 직후 `system_profiler SPDisplaysDataType`(또는 BetterDisplay UI)에서 남은 가상 디스플레이가 없는지 확인한다 — 중복 시리얼·잔존 디스플레이 누적 여부를 매 회 기록한다.

기록 항목:

| 항목 | 예상값 |
| --- | --- |
| 덮개 닫힘 후 VD 생존 | `system_profiler`에 열거 유지 |
| 스트리밍 지속 | 덮개 닫힘 후에도 태블릿 갱신 지속 |
| USB 키보드 반영 | 태블릿 화면에 타이핑 표시 |
| USB 마우스 반영 | 이동·클릭 표시 |
| 카드 상태 pill 표기 | (관찰값 기록) |
| B: Cmd+Q 후 VD 소멸 여부 | 질문에 대한 관찰 답 (수행 후 기록) |
| C: 5회 반복 후 잔존 VD 수 | 0 |

합격 기준: 덮개 닫힘 후 VD 생존 + 스트리밍 지속 + USB 키보드·마우스 반영이 모두 성립한다. B는 판정이 아니라 **질문과 관찰 답**으로 기록한다 — 설계상 정상 종료의 기대 동작은 Drop 정리이고, 크래시 시 잔존 여부는 미결 질문이다(답이 설계 기대와 다르면 EVIDENCE.md에 후속 과제로 남긴다). C의 합격은 5번째 중지 직후 잔존 가상 디스플레이가 정확히 0인 것이다.

## 검증 3: 태블릿 터치 — LCI1 역방향 주입

목표: `inputEnabled` 옵트인 후 태블릿 터치가 LCI1 주입 경로로 가상 디스플레이 위의 커서 이동·클릭으로 반영됨을 확인한다. docs/EVIDENCE.md의 입력 검증 경계(`inputEnabled=false` 표본) 갭을 소거한다.

절차:

1. 검증 1 상태(스트리밍 중, 덮개 열림 — 태블릿에 VD 렌더)에서 시작한다.
2. 필요하면 먼저 접근성 권한을 허용한다(카드의 권한 안내 — 시스템 설정 > 개인정보 보호 및 보안 > 접근성).
3. Host 세션 카드에서 해당 세션의 입력 토글("원격 조작 끔")을 눌러 "원격 조작 허용됨"으로 전환한다.
4. 태블릿 화면을 터치·드래그하고, Mac 커서가 가상 디스플레이 위에서 이동하는지 관찰한다.
5. 탭이 VD 위 UI 요소의 클릭으로 반영되는지 확인한다.
6. 입력 토글을 다시 끄고("원격 조작 끔") 터치가 무시되는지 확인한다.

기록 항목:

| 항목 | 예상값 |
| --- | --- |
| inputEnabled 전환 | "원격 조작 허용됨" 표기 |
| 터치 → 커서 이동 | VD 위 커서가 터치 좌표를 따라감 |
| 탭 → 클릭 | VD 위 요소에 클릭 반영 |
| 토글 Off 후 | 주입 중단 |

합격 기준: 태블릿 터치가 VD 위 커서 이동과 클릭으로 반영되고, 토글 Off 시 주입이 멈춘다. 이것이 충족되면 입력 경로까지 포함해 가상 디스플레이 경로의 E6가 완성된다.

## 검증 4: 절전 방어 — 10분 생존과 assertion

목표: 덮개 닫힘 10분 후에도 세션(VD + 스트리밍)이 생존하고 시스템이 수면에 빠지지 않음을 `pmset -g assertions`의 caffeinate 표시와 함께 확인한다.

절차:

1. AC 전원 연결을 확인한다(전제: `caffeinate -s`). 배터리에서는 `-i`로 강등되므로, 배터리 상태에서 수행하면 결과 표에 전원 상태를 남기고 AC에서 재수행한다.
2. 세션을 시작하고 검증 2 절차에 따라 덮개를 닫는다.
3. 덮개 닫힘 직후 `pmset -g assertions`를 실행해 caffeinate 프로세스가 만든 assertion 행(프로세스명 caffeinate)을 확인하고 assertion 종류와 PID를 기록한다.
4. 10분간 방치한다.
5. 10분 후: 태블릿 스트리밍 지속, `system_profiler SPDisplaysDataType`의 VD 생존, `pmset -g assertions`의 caffeinate 유지, 시스템이 수면에 빠지지 않았는지(태블릿 화면이 여전히 갱신되는지)를 확인한다.

## 실패 시 진단 가이드

증상별 확인 순서:

1. **"활성 화면이 없습니다"로 시작 실패** → by-design NoActiveDisplay다. 덮개를 열거나 외장 모니터 전원을 켠 뒤 다시 시작한다. `ioreg -r -k AppleClamshellState | grep ClamshellState`가 `Yes`면 아직 닫혀 있는 것이다. 덮개 닫힘 + 화면 공유 원격 사용 상태에서는 GUI 터미널에서 실행해도 활성 화면이 0개다(docs/dev-environment.md).
2. **"BetterDisplay가 필요합니다" 또는 엔진 사용 불가** → BetterDisplay 설치·실행 여부, 설정에서 CLI 접근 허용 여부, GUI 터미널에서 `which betterdisplaycli` 확인. Dock 실행 시 최소 PATH 문제면 사전 확인 A로 재현해 실행 경로를 바꿔 본다(Dock 대신 터미널 `open` 등).
3. **VD는 생성됐는데 태블릿이 검은 화면** → Viewer 카탈로그에서 가상 디스플레이(`Leftcar Virtual`)를 열었는지, 스트리밍 세션이 running인지 확인한다. 시스템 설정 > 디스플레이에서 VD가 확장 화면으로 잡혀 있는지도 확인한다(캡처 경로 문제).
4. **덮개 닫힘 후 세션 사망(태블릿 화면 정지)** → AC 전원 여부와 `pmset -g assertions`의 caffeinate 표시를 확인한다. 배터리(-i 강등) 상태였다면 AC에서 재수행한다. BetterDisplay 자체 설정(덮개 닫힘·디스플레이 자동 정리 계열)과 간섭하지 않는지 BetterDisplay UI에서 확인한다.
5. **"태블릿 화면 세션이 이미 실행 중입니다"** → 앞선 세션이 정리되지 않은 상태다. "중지"로 정리하거나 앱을 재시작한 뒤 진행한다. 재시작 후에도 상태가 남으면 검증 2-C 잔존 확인과 함께 기록한다.
6. **터치 입력이 반영되지 않음** → 입력 토글이 "원격 조작 허용됨"인지, 접근성 권한이 허용됐는지 확인한다. 권한 거부 시 카드 안내에 따라 시스템 설정 > 개인정보 보호 및 보안 > 접근성에서 허용한다.
