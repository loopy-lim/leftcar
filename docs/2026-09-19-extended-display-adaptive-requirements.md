# 확장 디스플레이 적응형 요구사항 — 사용자 요청 전달 (2026-09-19)

수신: 확장 디스플레이(v1, 미커밋) 구현 세션. 발신: 2026-09-19 사용자 요청.
충돌 방지: 이 문서는 요구사항만 담는다. 가상 디스플레이 관련 파일(`virtual_display.rs`, `VirtualDisplay/*`, Host UI 카드)은 구현 세션이 계속 소유한다.

## 사용자 요청 원문 요약

"꼭 고정되어 있는 확장이 아닌, tablet에 맡게 하고 사용자가 그것들을 쉽게 변하게 해야하지 않을까? 예를 들면 Parsec을 보자." — 직결+4K 스트리밍이 잘 동작하는 것을 확인한 뒤의 요청.

## 요구사항

1. **생성 기본값 = 연결 태블릿 실측**: 프리셋 고정이 아니라, 마지막/현재 연결 기기의 `viewerDisplay` 메트릭(이미 startStream에 첨부됨 — getDisplayMetrics)으로 가상 디스플레이 크기를 정한다. 연결 기기가 없으면 마지막 기기 메트릭, 그것도 없으면 현행 프리셋.
2. **UI 3단계 단순화 (Parsec식 최소 옵션)**:
   - "태블릿에 맞춤(자동)" — 기본값. 기기 메트릭 추종.
   - 프리셋 몇 개 (현행 셀렉트 유지).
   - 직접 입력 (픽셀) — DisplaySizeCard의 수동 입력 패턴 재사용.
3. **변경 적용**: 생성 시 최종 모드 확정 원칙 유지(모드 변경 금지 — §1.4 좀비 함정). 크기 변경은 destroy+recreate로 처리하고 UI는 "제거 중(~30s 비동기)" 상태 표시(§11 E-5).
4. **우선순위**: E-7(가상 디스플레이 스트리밍+입력) 검증이 선행 — 실물 입력 매핑 확인 전에 UI 고도화 금지.

## 참고

- 설계 본문: `docs/2026-09-18-extended-display-design.md` (§6 결정 4건, §11 v1 실측)
- 사용자가 이미 4K(확장 디스플레이 경유 추정) 스트리밍을 실측했고 성능에 만족 — 적응형은 편의 개선이며 성능 회귀 금지.
- Leftcar 쪽 다른 변경(복구·grants·커서·NACK)은 이 문서와 무관하며, 가상 디스플레이 파일에는 손대지 않았다.
