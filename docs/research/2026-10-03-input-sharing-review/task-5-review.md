## Findings

### F1 — P1: cancellation is not a fence around active transaction admission or final routing/owner commitment

Locations: `apps/viewer-expo/android/app/src/main/java/dev/leftcar/viewer/km/KmAccessibilityService.kt:43` and `:60-63`; `apps/viewer-expo/android/app/src/main/java/dev/leftcar/viewer/km/KmRuntime.kt:393-399`; `apps/viewer-expo/android/app/src/main/java/dev/leftcar/viewer/km/KmOwnObservation.kt:45-50`.

The attempt lock protects the main-thread local field write, but final commitment is a separate check-then-act operation. One valid execution is:

1. Helper applies/verifies the tuple and returns success.
2. Worker completes `fresh()` on service line 60, observing a current token and connection.
3. Main/thread calls `KmRuntime.stop()`, which synchronously cancels that attempt and queues `stopNow` behind the currently executing worker task.
4. Worker finishes the local-mask read and calls `routing.commitCapture(..., commitOwner)` or `routing.setMode(OBSERVE)` without consulting the attempt again. `commitCapture` checks only its physical-input revision/holds; cancellation does not change that revision.
5. The cancelled transaction can therefore return success and publish/acknowledge active ownership before queued cleanup runs. For CONSUME, physical key routing can become consuming after the cancellation has already returned. Eventual OFF cleanup does not make this an uncancelled commitment.

There is also an admission interleaving with the same cancellation design: a Stop arriving while the worker is in `api.prepare`, conflict checks, or the capture RPC cancels the current serial, but `configure()` subsequently executes an unconditional `begin()` and receives a new current serial. Runtime generation changes only inside queued `stopNow`, so the already-cancelled session's closure still returns true and this new attempt can issue nonzero local/system writes before Stop is processed. This is a fresh active attempt after Stop, not an already-issued remote RPC finishing late.

The proposal requires cancellation to invalidate pending active writes and fresh instance/id/generation/ticket fencing at ownership commit. Existing tests cancel from inside the helper callback, before the final `fresh()` begins (`KmOwnObservationTest.kt:160-178`), so they do not exercise either boundary above.

Narrow correction: give a Stop request a synchronously visible session/admission cancellation fence that cannot be reset by `configure.begin()` within that same session; then serialize the final attempt-validity decision plus routing/owner commit with attempt cancellation using a short local gate. Preserve the existing routing capture-ticket check inside that commitment and keep remote Binder calls and main-thread waits outside the gate. Audit `observationService` publication if it remains read from non-worker callers; a worker-only plain field should not become the authority for a synchronous cross-thread fence. A late in-flight system RPC still needs post-return OFF recovery; do not attempt to solve it by holding the watchdog/input monitor across IPC.

Focused regression coverage: (a) request Stop before configure admission while the current worker operation is paused; verify no later nonzero local/helper write or success publication, and (b) pause at the final local readback after `fresh()` succeeds, cancel, then resume; verify no CONSUME/OBSERVE commitment or owner callback. These can be driven through the existing production service/Runtime seams; no physical input is required.

### F2 — P2: the app-side observed getter is not validated before enabling the system subscription

Locations: `apps/viewer-expo/android/app/src/main/java/dev/leftcar/viewer/km/KmAccessibilityService.kt:46-59` and `:95-99`; `apps/viewer-expo/android/app/src/main/java/dev/leftcar/viewer/km/KmOwnObservation.kt:27-39`.

`connection()` resolves own connection id, cache endpoint, and local dispatch field. `configure()` reads the public service info and checks IME flags, but never invokes/resolves `observationPlatform.observed(info)`. The app-targeted `getObservedMotionEventSources` path is first exercised during OFF restoration. The shell getter successfully invoked by `KmBorrowedObservationEndpoint` is a different process/access path and does not prove app-side targeted access works.

Concrete unsupported-layout/access execution: own id/cache/local field access works; app-side targeted observed getter is unavailable or throws; shell get/set/get works. Current configure still writes nonzero local dispatch, applies a nonzero system tuple, commits routing, and reports observation supported. Only Stop discovers the missing required cleanup getter, making every restoration unconfirmable and leaving `cleanupFailed` despite this prerequisite being knowably unsupported before activation. The existing unsupported-member test makes the entire `connection()` fail (`KmOwnObservationTest.kt:121-126`), so it does not cover this independently missing member.

The approved targeted-access contract lists the own returned-ServiceInfo observed getter among required members and requires missing members/layout to fail before any nonzero subscription. Its availability is also essential to the helper-death public-OFF verification route.

Narrow correction: exercise/validate the exact app-side observed getter on the freshly obtained own `ServiceInfo` as a non-mutating prerequisite before either nonzero local dispatch or helper write, within the same fenced transaction. Keep the getter in OFF verification as well; do not substitute shell-only verification or relax cleanup confirmation. Add a production-platform seam case where only `observed()` throws while connection/local field access work; assert fixed capability failure, zero helper active calls, no active local mask/routing, and no owner commitment.
