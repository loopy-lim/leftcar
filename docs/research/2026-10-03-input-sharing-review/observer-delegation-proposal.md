## Partial-transition and targeted-access contract

The new helper method accepts a closed mode0=OFF,1=OBSERVE,2=CONSUME only; derives every mask/flag itself from the finite table; rejects unknown mode. It receives no arbitrary requested source bits or independent flag toggles. Non-OFF requires the existing app-bound live prepared authority and current owner; OFF recovery remains authorized for the exact own target even after input resources expire. Existing key/mouse lease and capture-ticket guards still run before any owner commit.

Configure remains an ordered native actor transaction. Before any system update, resolve exact current own instance and its returned framework connection id/Binder, required targeted members, metadata guard, and current generation/capture ticket. Change own local dispatch field on the main thread through a bounded completion with an attempt token, after which native worker performs the shell set+readback. A queued main write must check the same live instance/attempt token before writing; timeout/cancel marks that attempt invalid, so late work cannot restore an active mask. Commit ownership/routing only after exact system readback plus fresh same-instance/id/generation/ticket check. On cancellation/failure, invalidate all pending active writes, force local dispatch/routingOFF and execute confirmed system OFF recovery; no saved observing snapshot may be restored. No nested wait can depend on a main thread that is waiting for the worker. Unsupported member/layout or a missing own connection must fail before any nonzero system subscription.

Local framework bookkeeping is explicit: the own XML does not request input-method-editor behavior. Reject an unexpected current FLAG_INPUT_METHOD_EDITOR request before delegation, since bypassing the public setter must not skip its input-method initialization/removal side effects. Audit the exact deployed setter/send/onMotionEvent dispatch methods before implementation to confirm that mMotionEventSources is the sole required own local dispatch change and that no mInfo/cache lifecycle write is required; if this cannot be substantiated, stop this route. Never mutate arbitrary framework fields to make it work. Existing actual service getters remain the system readback; the private local field is not that evidence.

The6.1 targeted invoke and exact own-field access API are primary-documented; actual in-app compatibility remains a prerequisite, not a guarantee. Pin dependency and verify artifact digest/license plus exact required members without any addHiddenApiExemptions/setHiddenApiExemptions call. Required members: own AccessibilityService.getConnectionId, process-local AccessibilityInteractionClient.getConnection for that id, own AccessibilityService.mMotionEventSources, and own returned ServiceInfo.getObservedMotionEventSources for cleanup verification. Reflective shell connection proxy methods are limited to getServiceInfo/setServiceInfo. No discovery of arbitrary service ids, targets, IPC operations or windows. Native tests must verify the guard/rollback/generation order at the production adapter seam; actual device proof comes after code/security review and normal verified packaging. A failed feasibility prerequisite means retain explicit unsupported status and report the limit, never add broader bypasses silently.
