# 키보드·마우스 입력 공유 설정

Mac과 Android가 각자 자기 OS 화면을 유지하고, 설정한 화면 가장자리를 넘으면 마우스와 키보드의 입력 대상이 바뀌는 모드입니다. 연결한 Wi-Fi로 입력 이벤트만 전달합니다.

## 준비

두 기기를 같은 LAN/Wi-Fi에 연결하고 기존 Leftcar 페어링을 완료합니다. Mac의 시스템 설정 → 개인정보 보호 및 보안에서 Leftcar의 손쉬운 사용과 입력 모니터링을 허용합니다.

Android에 Shizuku를 설치하고 USB로 시작합니다. USB 디버깅의 기기 승인과 Shizuku 앱의 Leftcar 승인은 사용자가 직접 진행합니다. Shizuku의 **컴퓨터에 연결하여 시작**에서 현재 설치 경로가 포함된 ADB 명령을 복사해 실행합니다. 여러 기기가 연결되어 있으면 `adb -s <기기 일련번호> shell ...`로 대상 기기를 지정합니다.

Shizuku 13.6.0은 설치된 `libshizuku.so`를 직접 실행합니다. 예전 `.../Android/data/.../start.sh`는 이 버전에 존재하지 않을 수 있습니다. 이 차이는 [공식 13.6.0 시작 코드](https://github.com/RikkaApps/Shizuku/blob/v13.6.0/manager/src/main/java/moe/shizuku/manager/starter/Starter.kt)에서 확인했고, 현재 TB522FU에서 해당 바이너리로 시작했습니다. 비루트 Shizuku는 재부팅 후 다시 시작해야 할 수 있습니다.

Leftcar의 입력 공유 화면에서 Shizuku 권한과 접근성 설정을 확인합니다. 기기의 마우스 관찰 기능이나 입력 helper가 준비되지 않으면 공유는 꺼진 상태로 유지되고 이유가 표시됩니다. KeyBridge는 켜둔 채 사용합니다. Mac에 연결된 키보드를 공유하고 Android에는 외부 키 장치가 없는 경우에는 두 앱의 물리 키 처리 경로가 겹치지 않습니다. Android에 물리 키 장치를 연결해 Mac으로 입력을 전달하는 경우에는 KeyBridge의 입력 소유권 연동이 필요합니다. 현재 설치된 KeyBridge 0.3.4에는 이 연동 서비스가 없으므로 해당 조합은 시작을 차단하며, 미연동 장치가 공유 중 연결되면 공유를 중지합니다.

## 연결과 사용

Mac의 페어링된 기기에서 두 방향의 키보드·마우스 공유를 각각 허용합니다. 이 양방향 모드는 두 방향 모두 허용되어야 시작하며, 어느 한 방향을 취소하면 전체 공유를 중지합니다. Android에서 Mac을 선택하고 Android가 Mac의 왼쪽 또는 오른쪽에 놓였는지 지정한 뒤 공유를 시작합니다. 화면 위치는 실제 책상 배치와 맞춥니다.

커서가 설정한 공유 가장자리를 넘으면 반대 OS를 조작하고, 키보드 입력도 같은 OS로 들어갑니다. 정상적인 복귀는 공유 준비 상태를 유지합니다. 경계를 넘기 전에 키나 버튼을 누르고 있으면 해제한 뒤 이동합니다.

공유 중지는 앱의 중지 버튼 또는 Mac의 `Ctrl+Option+Command+Esc`를 사용합니다. 연결·Shizuku·권한이 사라지거나 watchdog이 만료되면 원격 키와 버튼을 해제하고 로컬 입력을 복원합니다. 재연결 후에는 다시 명시적으로 시작합니다.

## Android 자체 접근성 연결 관찰

Android 16의 마우스 관찰 설정은 이미 사용자가 켠 Leftcar 자체 접근성 서비스 연결에만 적용합니다. 네이티브 앱이 현재 자체 연결을 얻어 기존 승인된 Shizuku shell helper에 일시적으로 위임하며, helper는 닫힌 OFF/관찰/물리 입력 공유 모드에서 마우스 계열 관찰과 기존 키 필터만 설정합니다. 물리 마우스 독점은 기존 물리 장치 grab 경로에서 수행합니다. KeyBridge를 끄거나 다른 접근성 서비스를 변경할 필요가 없습니다.

이 경로는 Android 공개 SDK만으로 보장되는 연동이 아니라 Shizuku shell 권한과 제한된 비공개 API에 의존하며, OS/OEM 업데이트 호환성과 현재 기기 동작은 별도 검증 대상입니다.

이 경로는 고정 버전 HiddenApiBypass 6.1의 특정 메서드 호출과 자체 로컬 마우스 dispatch 필드 접근을 사용합니다. OS 전체 hidden API 정책이나 접근성 관찰 권한을 변경하지 않습니다. 실제 연결·필드·설정 readback을 확인하지 못하거나 예상치 못한 입력기 편집기 플래그가 있으면 시작하지 않습니다. 중지 시 자체 공개 설정 API로 마우스/관찰/키 필터와 로컬 dispatch를 OFF로 되돌려 확인하며, 확인 실패는 해제 실패 상태로 남아 재시작을 차단합니다. helper 종료만으로 관찰 해제가 확인된 것으로 처리하지 않습니다.

## 검증 범위

Android의 실제 시스템 커서·hover·드래그·휠, 양쪽 물리 키보드, 두 방향의 경계 이동, 연결 해제 후 로컬 복원은 실제 기기에서 확인해야 합니다. 코드 테스트·빌드·APK 생성은 이 물리 동작의 증거가 아닙니다. 이 문서는 설치와 검증 순서를 설명하며 실기기 통과를 주장하지 않습니다.

## 이 Mac의 개인 개발 서명

현재 개인 개발 인증서의 실제 Team ID는 `88WFD6M5FC`이며, 사용자가 개인 서명으로 전환을 승인했습니다. 기존 `SEVEN PICTURES` 회사 개발 인증서는 폐기 상태였고, 사용자 요청으로 로그인 키체인에서 제거했습니다. 앱 ID `leftcar.ll3.kr`와 설정 경로는 유지했습니다.

이 Mac에서 다음 내부 Host 빌드에도 같은 개인 인증서를 명시합니다.

```sh
LEFTCAR_HOST_SIGNING_IDENTITY=410C9E67CF6C81727268BEBB00ED4552DA11D64B bun run build host-macos-internal
```

다른 서명 주체로 바뀐 최초 실행에서는 Mac의 손쉬운 사용·입력 모니터링을 다시 허용해야 할 수 있습니다. 빌드 도구는 매번 서명을 검증하며, 이 명령은 설치나 OS 권한 승인을 수행하지 않습니다.
