# 뷰어 주도 가상 화면 크기 설계 (안 A)

상태: 사용자 설계 승인 2026-09-06. 기준 커밋 c0bef04 (main).
범위: 태블릿(확장 모드) 자동 매칭 + 수동 조정, Galaxy XR 창 비율 프리셋, 스트리밍 중 실시간 적용.

## 결정 사항

- 접근안 A: 뷰어 주도. 태블릿이 자기 화면 메트릭을 호스트에 알리고, 크기 결정·조정 UI를 태블릿 앱이 가진다. 호스트는 명령 수행만 한다.
- 적용 시점: 스트리밍 중 실시간. 가상 화면 모드 리사이즈 + reconfigureStream 조합, 스트림 재시작 없음.
- XR: Mac 가상 화면 해상도는 유지하고 창 비율·크기 프리셋만 지정(SpatialWindow ratio + 초기 bounds).

## 1. 자동 매칭 (연결 시)

- 뷰어가 스트림 시작 요청에 자기 디스플레이 메트릭(물리 px, 밀도)을 실어 보낸다.
- 호스트 매칭 계산: 태블릿 물리 px ÷ 2 = HiDPI 논리 크기(예: 2800×1752 → 논리 1400×876, scale 2). 논리 크기가 macOS 범위를 벗어나면 scale 1로 폴백.
- 확장 모드 세션 시작 시 일치하는 관리 화면이 없으면 자동 생성, 있으면 재사용.

## 2. 수동 조정 (태블릿, 스트리밍 중 실시간)

- 카탈로그에 "가상 화면 크기" 카드: 현재 크기 표시 + 프리셋(태블릿 매칭/1080p/2K/사용자 지정 px) + scale(1x/2x).
- 적용 = DisplayManager.resize(신규) + reconfigureStream. 실패 시 오류 표시 후 기존 크기 유지.

## 3. Galaxy XR

- Mac 가상 화면 해상도 불변. 창 비율 프리셋(16:10/16:9/4:3/세로)을 SpatialWindow ratio + 초기 bounds에 적용.
- XR 감지는 기존 기기 분기 재사용.

## 4. 오류·안전

- 자동 생성 화면도 기존 고유 관리 ID로 추적. 세션 종료 정리 정책 현행 유지.
- 리사이즈 중 프레임 복구는 기존 reconfigure 경로에 맡긴다(새 전송 경로 없음).

## 검증

- 매칭 계산·폴백: Rust·Kotlin 순수 함수 회귀 테스트.
- 리사이즈: Host Rust 검사 + 기존 reconfigure 테스트 통과.
- React 변경 후 루트 React Doctor 100/100, typecheck, 관련 vitest.
- 실기(Lenovo 태블릿, Galaxy XR) 연결 시: 연결→자동 크기→프리셋 전환→XR 비율 전환 확인. 미연결 시 미검증 항목으로 명시.
