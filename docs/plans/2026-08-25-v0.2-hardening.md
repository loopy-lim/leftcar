# Leftcar v0.2 하드닝 구현 계획 (보안·검증·릴리스·아키텍처)

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** v0.1.1 이후 누적된 5개 발전 방향을 완수해 v0.2 공개 릴리스를 가능하게 만든다: (1) 미디어/입력 패킷 인증을 평문 토큰에서 HMAC으로 교체, (2) Windows 백엔드 물리 검증(E13), (3) 장기 안정성 증명(E7 soak), (4) 릴리스 서명·위생, (5) 이중 트랙 아키텍처 정리.

**Architecture:** 미디어 인증은 세션 토큰에서 HKDF-SHA256으로 파생한 32B 세션 키를 사용해 모든 와이어 패킷(media, LCI1 입력, LCA1 ACK, LCP1 프로브, LCT1 종료, LCF1 피드백, LCH1 챌린지)에 HMAC-SHA256 태그(16B truncate)를 붙인다. 기존 접미사 토큰 비교(`wire.rs:137`)를 상수시간 HMAC 검증으로 대체하되, 와이어 포맷 버전 헤더는 유지해 구형 뷰어/호스트 혼합 시 명시적 거부로 떨어지게 한다. 키 파생은 호스트 `startStream` 시점에 수행하고 기존 토큰 전달 경로(control.rs → backend trait → macOS FFI/Windows 백엔드, 그리고 제어 응답 → viewer JNI)를 그대로 재사용한다.

**Tech Stack:** Rust (hmac, sha2, zeroize, keyring crate), Swift (CryptoKit/CommonHMAC), Kotlin (없음 — Rust JNI가 검증), TypeScript (없음 — 미디어는 TS를 거치지 않음), GitHub Actions (Windows runner, signing)

**설계 배경:** 2026-08-25 코드베이스 리서치(4개 병렬 조사: 아키텍처 맵, 문서/로드맵, WIP 분석, 갭/리스크 스캔). 이 계획은 리서치에서 확인된 구체적 약점(`wire.rs:137` 평문 토큰 접미, `pairing.rs:288` 평문 JSON 저장, Windows 백엔드 테스트 0건·물리 검증 0회, `build.gradle:122` debug 서명, `crates/` 프로덕션 미사용)을 근거로 작성됐다.

### Task 3: 호스트 백엔드 교체 — startStream 키 파생 + 송수신부

**Files:**
- Modify: `apps/host-desktop/src-tauri/src/control.rs` (startStream 내)
- Modify: `apps/host-desktop/src-tauri/src/backend.rs` (CaptureBackend 트레이트)
- Modify: `apps/host-desktop/src-tauri/src/ffi.rs` (macOS shim 호출)
- Modify: `apps/host-desktop/src-tauri/src/windows_backend/mod.rs`
- Modify: `native/android-viewer/src/jni.rs` (세션 키 저장 + 검증)
- Modify: `apps/viewer-expo/src/launch-stream.ts` (startStream 응답에서 세션 키 수령 — 기존 token 필드 재사용 여부 검토 후 `mediaKey` 필드 추가)

**Step 1:** `control.rs` startStream이 세션 토큰에서 `derive_session_key`를 1회 수행해 백엔드에 전달한다. 백엔드 트레이트의 `start` 파라미터에 키를 추가하고(또는 토큰 대신 키 전달으로 수렴), macOS는 `ffi.rs`가 새 심볼 `leftcar_capture_start_v5(key)`로 전달, 미지원 shim 폴백 체인(ffi.rs:271 패턴)에 v5를 선두로 추가.

**Step 2:** `CaptureShim.swift`: `viewerControlToken`을 세션 키로 교체. 모든 송신(`sendMediaDatagram`, `sendTCPFrame` 인증 프레이밍, `notifyViewerTermination`, challenge)과 수신 검증(`input receiver`, `parse_ack` 상당 경로, LCF1 피드백 검증 `:2202`)을 HMAC으로. Swift는 `CryptoKit.HMAC<SHA256>` 사용 — NDK/JS와 동일 알고리즘이므로 상호작동 보장. **Swift에는 wire.rs 테스트 벡터와 동일한 고정 벡터 단얫 테스트를 추가할 수 없다(XCTest 부재) — 대신 디버그 빌드에서 앱 시작 시 자체 점검 후 로그 출력하는 self-check 함수를 넣고, macOS e2e에서 실측으로 검증한다.**

**Step 3:** `windows_backend/mod.rs`: `termination_token`(47)을 파생 키로 교체, `prove_udp_reachability`(171)의 챌린지도 HMAC으로.

**Step 4:** `jni.rs`: `prepare_port`가 세션 키를 받아 저장하고, 미디어/입력/프로브 송신(`encode_input`, `encode_latency_probe`, `request_idr`)과 수신 검증이 `seal`/`open`을 사용. ViewerNative.kt `prepareStream` 시그니처에 키 전달 추가(Kotlin은 문자열 hex 전달 → Rust에서 디코딩).

**Step 5:** 구형 접미사 토큰 경로 전면 제거: `wire.rs`의 `authenticated()`, viewer의 접미사 비교. **혼합 버전(구형 뷰어 + 신형 호스트, 그 반대)은 미디어 핸드셰이크 실패로 명시적 종료되어야 한다** — LCH1 챌린지가 HMAC이므로 자동으로 성립한다. 혼합 버전 시나리오를 e2e 테스트(control_e2e.rs에 FakeBackend 기반)로 추가.

**Step 6:** 전체 검증 명령 실행 + 실기기 1회: TB710FU에서 스트림 시작 → 화면 수신 → 원격 입력 → 종료 사슬 확인. EVIDENCE.md에 "미디어 HMAC 인증" 항목 추가(부분 달성 표기 — 물리 Windows는 제외).

- **HMAC 정합성**: 동일 고정 벡터를 wire.rs / media_datagram.rs 양쪽 테스트가 검증 (드리프트 방지 핵심 장치)

- **soak**: 수동 60분 + 정량 판정 기준(지연 +20%, 메모리 비선형, 자가종료 0)

## 범위 제한 (하지 않을 것)

- QUIC/DTLS 전면 전환 (ADR-0004 bake-off는 별도 유보 — HMAC은 그 이전의 저비용 경량화)
- 제어 평면 TCP의 TLS (로컬 신뢰망 가정 유지, docs/07 v0.1.1 명시 범위)
- 창 단위 캡처 (roadmap 후속, 이 계획 외)
- Galaxy XR 실기기 게이트 (기기 미보유)
- 텔레메트리/크래시 리포트 (로컬-only 원칙 유지)
- SBOM/fuzz (Phase D 서명과 별도 이후 작업)

## 리스크와 롤백

- **HMAC 전환은 프로토콜 브레이킹**: 구형 뷰어 APK가 신형 호스트에 연결하면 미디어 핸드셰이크가 실패한다. 의도된 동작이나 v0.2 릴리스 노트에 명시해야 한다. 롤백은 git revert로 완전 가능(세션 키는 메모리성).
- **Keychain 저장(Task 생략됨 — 아래 참고)**: 호스트 토큰의 Keychain/DPAPI 저장은 이 계획에서 **별도 후속 작업으로 분리**했다. 이유: `keyring` 크레이트 도입이 macOS/Windows 자격증명 저장소 접근 권한·서명 요구를 가져와 Phase D(서명)와 결합되어야 하기 때문. v0.2에서는 0600 JSON 유지, v0.3 후보로 기록.
- **vendor 삭제는 되돌림 어려움 없음**(git 이력 보존).
