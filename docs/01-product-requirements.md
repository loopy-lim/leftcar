# 제품 요구사항

문서 상태: 제안안 0.1  
제품 코드명: Leftcar  
대상 독자: 제품 책임자, macOS/Windows 시스템 개발자, Android 개발자, Rust 개발자, QA 담당자

## 1. 문제 정의

Galaxy XR에서 데스크톱 화면을 낮은 지연으로 계속 관찰하고, 서로 다른 앱이나 모니터를 동시에 놓고 보면서 필요한 순간에 제어할 수 있는 간단한 도구가 필요하다. 기존 원격 데스크톱 제품은 계정, 중계 서버, 파일 전송, 오디오까지 포함하는 경우가 많다. Leftcar의 문제는 더 작다.

> 데스크톱의 선택된 픽셀을 가능한 한 빨리 Galaxy XR에 전달하고, 여러 소스를 한눈에 안정적으로 보여 주며, Host가 허용한 세션만 낮은 지연으로 제어한다.

원격 입력은 영상과 같은 수준의 기본 권한으로 취급하지 않는다. 세션별 Host 승인, macOS 손쉬운 사용 권한, 포커스 이탈 시 전체 해제, 좌표 정규화, 신뢰 가능한 키/버튼 전달을 독립 경계로 두고 화질과 다중 스트림 안정성을 유지한다.

## 2. 목표 사용자와 대표 상황

### 2.1 개발자 모니터링

- 편집기, 빌드 로그, 서버 대시보드, 테스트 장치 화면을 동시에 본다.
- 실제 입력은 Mac 또는 PC의 로컬 장치와 Galaxy XR에 연결된 키보드/마우스를 모두 사용할 수 있다.
- Galaxy XR는 넓은 관찰 화면이자 선택적으로 원격 입력을 보내는 화면 역할을 한다.

### 2.2 운영 상태 관찰

- 여러 서비스의 상태창, 로그, 그래프를 계속 띄운다.
- 대상 창 하나가 멈추거나 사라져도 나머지 스트림은 유지된다.
- 중요한 타일을 확대하고 나머지는 낮은 프레임률로 유지한다.

### 2.3 미디어와 장기 작업 관찰

- 렌더링, 인코딩, 다운로드, 테스트 진행 화면을 관찰한다.
- 오디오는 필요하지 않다.
- 장시간 사용 중 지연이 누적되지 않아야 한다.

## 3. 제품 원칙

### P-01 명시적 원격 입력

원격 입력은 각 스트림에서 기본적으로 꺼져 있고 Host 사용자가 명시적으로 켠 경우에만 동작한다. 포인터 이동은 영상 FPS의 2배를 목표로 최신값만 전송하고, 키·버튼·휠·전체 해제는 ACK/재시도로 전달한다. 입력은 Rustra/JSON 제어 계약에 넣지 않는다.

### P-02 픽셀 경로 우선

캡처, 인코딩, 전송, 디코딩, 표시의 프레임 경로를 UI 프레임워크와 분리한다. 압축 영상이 TypeScript 객체, JSON, Rustra command payload를 거치지 않는다.

### P-03 여러 독립 source와 여러 독립 창

사용자는 물리 디스플레이 또는 앱 창을 여러 개 선택할 수 있다. 각 source에는 독립 스트림 ID, `StreamActivity` task, decoder, 품질 상태가 있다. Android XR Home Space는 각 task를 독립적인 시스템 창으로 보여 준다. 한 source의 오류나 창 종료가 전체 세션을 종료하지 않는다.

### P-04 XR 최소 사용

기본 앱은 Android 대화면 앱으로 동작한다. OpenXR, Unity, 시선 추적, 손 추적, 공간 앵커, 공간 패널을 요구하지 않는다.

### P-05 로컬 우선

첫 배포는 같은 신뢰 네트워크에서의 직접 연결만 지원한다. 공개 인터넷 중계, 계정 서버, 클라우드 저장소는 범위 밖이다.

### P-06 관측 가능한 품질

“빠르다”를 감상으로 판정하지 않는다. 각 프레임 단계와 glass-to-glass 지연, 드롭, 네트워크, 발열을 측정한다.

### P-07 기본 거부

명시적으로 페어링된 Viewer만 source 목록을 보고 캡처를 요청할 수 있다. Host에서 사용자가 source를 승인해야 한다.

## 5. 사용자 흐름

### 5.1 최초 페어링

1. 사용자가 Mac에서 Leftcar Host를 실행한다.
2. Host가 화면 기록 권한 상태를 확인하고 필요한 시스템 안내를 보여 준다.
3. 사용자가 “새 Viewer 연결”을 누른다.
4. Host가 2분 이내 만료되는 QR을 표시한다.
5. Galaxy XR에서 Viewer를 실행하고 QR을 스캔한다.
6. Viewer가 Host 인증서 지문과 일회용 토큰을 검증한다.
7. Host가 연결 요청의 장치 이름과 지문을 보여 주고 사용자가 승인한다.
8. 양쪽이 장기 장치 키를 저장하고 일회용 토큰을 폐기한다.
9. Viewer는 아직 source를 볼 수 없다. Host 사용자가 캡처 source를 선택해야 한다.

### 5.2 다중 앱 보기

1. Host에서 사용자가 “소스 추가”를 선택한다.
2. 운영체제 제공 선택기 또는 Leftcar 목록에서 앱 창 A를 고른다.
3. 앱 창 B와 디스플레이 C를 같은 방식으로 추가한다.
4. Host가 각 source에 기본 품질 profile을 지정한다.
5. Viewer가 source A, B, C에 대해 서로 다른 세 `StreamActivity` task를 연다.
6. Galaxy XR가 세 task를 별도 Home Space 창으로 표시한다.
7. 사용자가 시스템 창 테두리로 각 창을 이동하거나 크기를 바꾼다.
8. 초점과 창 크기 변화에 따라 각 source의 품질 profile이 독립적으로 바뀐다.

### 5.3 네트워크 단절과 복구

1. Viewer가 패킷 도착 중단을 감지한다.
2. 마지막 프레임을 무기한 정상 화면처럼 유지하지 않고 “재연결 중” 상태를 겹쳐 표시한다.
3. 지수 backoff와 jitter를 적용해 직접 연결을 재시도한다.
4. 연결이 돌아오면 세션 버전과 source 목록을 재동기화한다.
5. Host가 여전히 승인한 source만 다시 시작한다.
6. 첫 IDR 프레임이 표시되기 전까지 복구 완료로 표시하지 않는다.

### 5.4 source 종료

1. 캡처하던 앱 창이 닫힌다.
2. 해당 source만 `source_unavailable` 상태가 된다.
3. 나머지 타일은 중단 없이 계속 재생된다.
4. Host가 같은 앱의 새 창을 자동으로 임의 선택하지 않는다.
5. 사용자가 새 source를 명시적으로 선택하거나 타일을 제거한다.

## 6. UX 상태 모델

Viewer 전체 상태:

```text
unpaired
  -> pairing
  -> paired_offline
  -> connecting
  -> connected_empty
  -> connected_streaming
  -> reconnecting
  -> paired_offline

any -> revoked   # Host에서 폐기됨. 재페어링 필요
```

stream window 상태:

```text
idle
  -> negotiating
  -> waiting_keyframe
  -> playing
  -> degraded
  -> reconnecting
  -> playing
  -> suspended   # stopped/숨김 상태의 grace period 경과. 다시 보이면 negotiating부터 재개

any -> source_unavailable
any -> permission_revoked
any -> decoder_failed
any -> stopped
```

상태 이름은 [Rustra 제어 계약](04-rustra-control-contracts.md)의 `PairingState`와 `StreamPhase` enum에 대응한다. 상태마다 사용자가 이해할 수 있는 설명, 재시도 가능 여부, Host에서 필요한 행동을 보여 준다. 내부 오류 코드만 그대로 노출하지 않는다.

## 7. 성능 목표

아래 수치는 구현 결과가 아니라 **검증할 제품 목표**다. Galaxy XR 실기기 측정 전에는 달성했다고 표현하지 않는다.

### 7.1 기준 profile

| profile | source 구성 | 우선 목표 |
| --- | --- | --- |
| S1 | 1920x1080 60fps 1개 | 가장 낮은 지연 |
| S2 | 2560x1440 60fps 1개 | 코드와 텍스트 선명도 |
| M2 | 1920x1080 30fps 2개 | 두 앱 동시 관찰 |
| M4 | 1920x1080 30fps 4개 | 다중 대시보드 |
| F4 | 주 타일 1440p60 1개와 보조 720p15 3개 | 실사용 적응형 구성 |

### 7.2 목표 지표

| ID | 지표 | 목표 | 필수 여부 |
| --- | --- | --- | --- |
| NFR-001 | LAN glass-to-glass 지연 | S1 p50 50ms 이하, p95 80ms 이하 | 필수 |
| NFR-002 | 장시간 지연 누적 | 60분 동안 초기 p50 대비 16ms 초과 증가 없음 | 필수 |
| NFR-003 | 안정 LAN 표시 프레임 드롭 | 10분 평균 1% 이하 | 목표 |
| NFR-004 | 네트워크 복구 후 첫 표시 | 연결 회복 후 1초 이내 | 필수 |
| NFR-005 | source/창 단위 장애 격리 | 한 source 또는 Activity 실패가 다른 재생을 중단하지 않음 | 필수 |
| NFR-006 | Viewer 메모리 | M4 30분 동안 지속 증가 없음 | 필수 |
| NFR-007 | 발열 | 60분 후 thermal severe로 지속 고정되지 않음 | 목표 |
| NFR-008 | 앱 재개 | background 30초 후 3초 안에 상태 복구 | 필수 |
| NFR-009 | 제어 명령 응답 | LAN p95 150ms 이하 | 목표 |
| NFR-010 | 페어링 비밀 만료 | 생성 후 2분 이내 | 필수 |

stretch goal은 S1 p50 35ms 이하, p95 50ms 이하다. 이 수치는 기준선 통과 후에만 최적화 목표로 사용한다.

## 8. 화질 원칙

1. 첫 코덱은 기기 호환성이 가장 높은 H.264로 한다.
2. sRGB SDR을 기준 색공간으로 한다.
3. 하드웨어 디코더가 보장하지 않는 4:4:4를 v1 요구사항으로 두지 않는다.
4. 텍스트 선명도는 고정된 샘플 화면과 OCR/SSIM 보조 지표, 사람 검수로 측정한다.
5. 해상도보다 지연 안정성을 먼저 지킨다. 큐를 늘려 화질을 유지하지 않는다.
6. 새 프레임이 밀리면 오래된 미표시 프레임을 버린다.
7. 초점이 없거나 작은 stream window는 시각적 중요도에 따라 해상도와 FPS를 낮출 수 있다.
8. 색 정확도, HDR, wide gamut은 별도 단계에서 다룬다.

## 9. 호환성 요구사항

### macOS

- 1차 기준: macOS 15 이상
- ScreenCaptureKit 시스템 선택기와 권한 모델을 따른다.
- 앱 창과 물리 디스플레이를 지원한다.
- 캡처 앱 자체를 제외할 수 있어야 한다.

### Windows

- 1차 기준: Windows 11의 현재 지원 버전
- Windows.Graphics.Capture를 기본 창/디스플레이 캡처 API로 검증한다.
- Desktop Duplication은 전체 디스플레이 fallback 후보로 둔다.
- GPU device lost와 크기 변경을 테스트한다.

### Galaxy XR

- Samsung Galaxy XR 실기기를 필수 품질 게이트로 둔다.
- 일반 Android 앱, Home Space, resizable activity를 기본으로 한다.
- Android 15 이상의 multi-instance System UI opt-in과 document task launch를 사용한다.
- Hub와 `StreamActivity` 인스턴스가 configuration change와 독립 task lifecycle을 견뎌야 한다.
- MediaCodec capability를 런타임에 조사하고 결과를 진단 화면에서 내보낸다.
- 제조사가 보고하는 코덱 상한을 동시 다중 디코더 보장으로 해석하지 않는다.

## 10. 수용 기준

v1 후보는 다음을 모두 만족해야 한다.

- [ ] 실제 Mac과 Galaxy XR가 계정 서버 없이 안전하게 페어링된다.
- [ ] 사용자가 선택한 서로 다른 앱 창 4개를 독립 Home Space 창으로 동시에 볼 수 있다.
- [ ] 최소 S1, M2, F4 profile의 E6 종단간 증거가 있다.
- [ ] S1이 NFR-001 지연 목표를 만족한다.
- [ ] 60분 실행에서 지연 누적, 메모리 지속 증가, 반복 크래시가 없다.
- [ ] 앱 창 하나를 닫아도 나머지 스트림이 재생된다.
- [ ] Wi-Fi를 10초 끊었다 켜면 승인된 source가 자동 복구된다.
- [ ] Viewer가 background/foreground 전환 후 자원 누수 없이 복구된다.
- [ ] 패킷 캡처에서 영상과 제어 데이터가 평문으로 보이지 않는다.
- [ ] Viewer에서 호스트 입력을 전송할 수 있는 코드 경로와 프로토콜 메시지가 없다.
- [ ] 모든 수동 검증 결과가 장치/빌드 정보와 함께 보관된다.

## 11. 출시 중단 조건

다음 중 하나라도 해당하면 beta 배포를 중단한다.

- 페어링되지 않은 장치가 source 목록 또는 프레임을 받을 수 있다.
- 세션 종료 뒤에도 Host가 화면을 계속 캡처한다.
- 영상 또는 키 material이 기본 로그에 기록된다.
- 지연이 시간이 지날수록 계속 누적된다.
- 한 source 또는 stream window 오류가 다른 창의 반복 크래시를 유발한다.
- 보호 콘텐츠를 우회하려는 동작이 발견된다.
- Galaxy XR 실기기에서 하드웨어 디코더 대신 알림 없는 소프트웨어 fallback이 발생한다.
