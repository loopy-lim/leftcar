# Leftcar 랜딩 디자인 가이드 (design.md)

- 성격: **의사결정 + 규칙 문서.** 이후 랜딩/페이지 작업은 이 문서를 따른다.
- 근거: `site/DESIGN-AUDIT.md`(구조 감사 §2.1~2.4), `site/AI-LOOK-REVIEW.md`(탈AI 진단), `site/IMPROVEMENT-PLAN.md`(통합 실행 계획), 그리고 **현재 워킹트리의 실제 값**(`site/src/index.css`, `site/src/components/**`, `site/src/content/site.ts`) 대조 검증.
- 원칙: 문서가 코드보다 앞서지 않는다. 아래 기록된 값은 실제 CSS와 일치하며, 코드를 바꿀 때는 이 문서를 먼저 고친다.
- 상위 문서와의 관계: DESIGN-AUDIT은 진단·지시, IMPROVEMENT-PLAN은 실행 항목, 이 문서는 **실행 이후에도 유지되는 기준선**이다. 상충 시 이 문서의 확정 판정을 따른다.

## 1. 디자인 원칙 — 금지 패턴과 대안

이 사이트의 기준은 "AI가 만든 것 같은가?"가 아니라 그 반대다. 아래 6개 패턴은 생성 페이지의 상징적 관습이며, **새 요소를 추가할 때도, 기존 요소를 손질할 때도 금지한다.**

### G1. pill 배지 남용 — 금지
- **금지**: `border-radius: 999px` + surface + border 형태의 pill에 사실 전달용 텍스트(라이선스, 버전, 상태)를 담는 것. pill 크롬이 정보보다 앞선다.
- **대안**: 단순 사실은 **텍스트 한 줄**(`--text-sm`, `--text-dim`, 쉼표 나열). 히어로 배지는 "MIT 라이선스, 오픈 소스, v0.1.4" 텍스트로 강등한다(현재 `Hero.css`의 `.hero-badge` pill 999px는 IMPROVEMENT-PLAN 2-1로 제거 대상 — 잔존 시 위반).
- **판정법**: 그 텍스트가 pill 없이 읽어도 자연스러우면 pill을 붙이지 않는다.

### G2. 균일 칩 그리드 — 금지
- **금지**: 표면·크기·형태가 같은 카드/칩을 2열 이상으로 반복 배치해 서로 다른 질문(기능/보안/상태)을 같은 그릇에 담는 것.
- **대안**: 콘텐츠 성격에 맞는 그릇을 쓴다 — §3 매트릭스 참조. Features만 카드, Security는 밴드+리스트 행, Status는 정의형 행.

### G3. 빈 상자 모식도 — 금지
- **금지**: 내용이 없는 테두리 상자를 점선으로 잇고 "→" 텍스트 화살표를 얹은 추상 다이어그램. 증거 없는 모식도는 "보여 줄 게 없다"는 인상을 준다.
- **대안**: (a) 최선 — 실제 앱 스크린샷(PC 캡처 + Android 프레임). (b) 확보 불가 시 **컴포넌트 삭제**(현재 `Diagram`이 이 대상 — 저장소에 실물 캡처가 없으면 제거가 정답). (c) 유지 시에도 빈 `.window-body` 대신 실제 어휘("디스플레이 1", "화면", "입력")를 넣는다.
- **판정법**: 그 자리에 실물 증거(스크린샷)를 놓을 수 없다면 그림을 넣지 않는다.

### G4. 획일적 "~합니다" 종결과 균등 문장 길이 — 금지
- **금지**: 페이지 전체가 같은 길이의 "~합니다/…습니다" 설명문 나열인 것. 어조 편차 0은 하나의 목소리가 아니라 평균값이다.
- **대안**: 강조하는 체언 종결 1개("PC 화면을 폰에서, 여러 개로."), 짧은 단문("화면은 민감합니다."), 상황 서술형 첫 문장("~입니다" 정의형 회피)을 섞는다. 상세는 §4.

### G5. 무근료 중앙정렬 — 금지
- **금지**: 섹션 제목·리드·노트·푸터까지 전부 중앙정렬하는 것. "전부 중앙"은 랜딩 템플릿 관습이며 요소별 재량이 0이라는 신호다.
- **대안**: **본문형 콘텐츠 섹션(Security, Status)의 제목·리드·노트는 좌측 정렬** — 리스트·행과 시선 축을 맞춘다. 중앙정렬을 허용하는 곳은 히어로(헤드라인·subcopy)와 스택 스트립뿐이며, 히어로도 CTA 행은 좌측으로 꺾어 완전 대칭을 깨는 것이 기본이다. 새 섹션의 정렬 축을 정할 때는 "리스트와 눈이 어디서 만나는가"로 판단한다.
- 참고: 현재 `index.css`의 `.section-title`/`.section-lead`가 `text-align: center`로 정의되어 있는데, 이는 Security/Status에서 좌측 정렬로 재정의해 상쇄한다(2026-09 기준 미적용 — IMPROVEMENT-PLAN 2-5).

### G6. 텍스트를 무조건 박스에 넣는 습관 — 금지
- **금지**: 나열이면 충분한 텍스트(기술 스택 등)를 surface+border 박스로 감싸는 것. 서로 다른 컴포넌트가 같은 "박스에 넣기" 해법을 쓰면 템플릿 흔적이 된다.
- **대안**: 인라인 텍스트 나열 — "Rust workspace, Tauri 2, Expo/React Native, 네이티브 캡처/디코더, CI" (`--text-sm`, `--text-dim`). 박스는 §3에서 허용한 곳(Features 카드, 다이어그램 컨테이너에 한함)에만.
- **판정법**: 박스가 정보를 더 읽기 쉽게 하는가, 아니면 그냥 장식인가?

### 핵심 금지 규칙 5개 (요약 — 후속 구현이 반드시 따를 것)

1. **pill 배지(`border-radius: 999px`)에 사실 텍스트를 담지 않는다** — 텍스트 한 줄로 강등.
2. **같은 카드/칩 그리드를 섹션에 반복하지 않는다** — §3 매트릭스의 그릇을 쓴다.
3. **빈 상자+점선+텍스트 화살표 모식도를 만들지 않는다** — 실물 스크린샷 또는 삭제.
4. **본문형 섹션(Security/Status)을 중앙정렬하지 않는다** — 히어로 외에는 좌측이 기본.
5. **나열 텍스트를 박스에 넣지 않는다** — 인라인 텍스트가 기본. 박스는 Features 카드만.

## 2. 디자인 토큰 — 확정판

`site/src/index.css`의 실제 값과 DESIGN-AUDIT §2.1~2.3을 대조해 확정했다. **양자가 일치하므로 아래 표가 곧 코드 기준이다.**

### 2.1 타입 스케일 — 7단계만 사용

현재 `index.css`에 정의된 값 그대로. 이 외 크기·clamp 직접 사용 금지, 단위는 rem만.

| 토큰 | 값 (index.css 실측 일치) | 무게/행간 (컴포넌트에서 적용) | 용도 |
|---|---|---|---|
| `--text-hero` | `clamp(2.25rem, 5vw, 3.25rem)` | 700 / lh 1.15 | 히어로 헤드라인 (유일) |
| `--text-2xl` | `clamp(1.5rem, 3vw, 2rem)` | 700 | 섹션 제목 (`.section-title`) |
| `--text-xl` | `1.375rem` | 600 | 예비 — 사용 자제 |
| `--text-lg` | `1.125rem` | 400 / `--text-dim` | 섹션 리드 (`.section-lead`) |
| `--text-md` | `1rem` | 400 | 본문, 카드/행 설명 |
| `--text-sm` | `0.875rem` | 500~600 | 카드·행 제목, 배지 텍스트, 상태 라벨 |
| `--text-xs` | `0.8125rem` | 400~600 | 보조 노트, 스택 소제목, 푸터 저작권 |

- 위계 규칙: h1은 1개(히어로), h2는 섹션당 1개, h3는 카드/행 제목. 히어로와 섹션 제목 사이에 새 크기를 넣지 않는다.
- 글꼴: **디스플레이 = Wanted Sans Bold(700) 1웨이트 커스텀 서브셋 self-host, 본문 = 시스템 UI 스택** (FONT-DECISION.md §3.1 확정). 토큰은 `--font-display: "Wanted Sans", var(--font-sans)`이며 히어로 헤드라인(`.hero-headline`)과 섹션 제목(`.section-title`)에만 적용한다. 서브셋은 `public/fonts/WantedSans-Bold.subset.woff2`(37.2KB, 사이트 사용 문자 387자 기준 — 원본 667KB 대비 94% 절감)이며, 카피 대폭 변경 시 `cd site && ./scripts/subset-font.sh`로 재생성한다. 라이선스 고지는 `site/LICENSE-fonts.md`, OFL 원문은 `public/fonts/OFL.txt`. CSP `font-src 'self'`와 정합(외부 CDN 참조 0건), `<link rel="preload" as="font" crossorigin>` 상대경로 1건 적용.
- 코드 계열(`code, kbd, samp, pre`)은 ui-monospace 스택 유지.

### 2.2 스페이싱 — 8단계 + 섹션 리듬

현재 `index.css` 정의 그대로. **px 직접 사용 금지**(1px 보더 제외). 현재 `Diagram.css`의 `padding: 10px`/`gap: 8px` 2건은 IMPROVEMENT-PLAN 3-1로 치환 대상 — 잔존 시 위반.

| 토큰 | 값 |
|---|---|
| `--space-1` | `0.25rem` |
| `--space-2` | `0.5rem` |
| `--space-3` | `0.75rem` |
| `--space-4` | `1rem` |
| `--space-5` | `1.5rem` |
| `--space-6` | `2rem` |
| `--space-7` | `3rem` |
| `--space-8` | `4rem` |

- **섹션 세로 패딩은 `--section-y: clamp(3rem, 7vw, 4.5rem)` 하나로 통일.** 섹션 간 추가 margin 금지. 유일한 예외: 스택 스트립은 `calc(var(--section-y) / 2)` 사용이 허용됨(현재 `StackBadges.css` 실측 일치).
- 컨테이너: `max-width: 1024px`, 좌우 패딩 `--space-4`. 리드/리스트의 좁은 열은 `max-width: 768px`.
- 카드 내부: 패딩 `--space-5`, 제목-본문 간격 `--space-3`.
- 리듬 변화는 **배경 밴드로만**: Security의 full-bleed `--surface` 밴드 + 상하 1px 보더(현재 `.security-band` 실측 일치). 다른 섹션에 밴드를 추가하지 않는다.

### 2.3 색상 — 6토큰, accent 3용

현재 `index.css`의 6토큰 그대로. 신규 색상 토큰 추가 금지.

| 토큰 | 값 |
|---|---|
| `--bg` | `#0b0e14` |
| `--surface` | `#11151f` |
| `--border` | `#1f2733` |
| `--text` | `#e6ebf4` |
| `--text-dim` | `#97a3b6` |
| `--accent` | `#4cc2a8` |

- **accent 사용처는 3종 한정**: ① primary CTA 배경 ② 본문 링크 ③ Status의 "사용 가능" 신호 1곳(macOS Host).
- 배지·스트립 등 중립 요소는 `--surface`+`--border`+`--text-dim` 조합. accent 틴트 금지.
- 장식적 선·라벨(다이어그램 등)은 accent 대신 `--text-dim`.
- 팔레트 자체(다크 네이비+청록)의 근거 결정은 §5로 보류 — 보류 중 색 값을 바꾸지 않는다.

## 3. 컴포넌트 패턴 — 사용처 매트릭스

| 패턴 | 구조 | 사용처 | 금지 사용처 |
|---|---|---|---|
| **카드** (surface+border, radius 12px, 패딩 `--space-5`) | 제목(`--text-sm` 600)+설명(`--text-md`) | **Features 4개만** (2열 그리드, gap `--space-5`) | Security/Status/스택에는 금지(G2) |
| **밴드 + 리스트 행** (full-bleed surface, 상하 1px 보더, 카드 크롬 없음) | 행 제목(`--text-sm` 600)+설명(`--text-md`), 2열 그리드(768px+) | **Security 4개** | 밴드를 다른 섹션에 복제 금지 |
| **정의형 행** (좌 항목명 / 우 상태 라벨, 행 사이 `--border` 구분선) | 항목명(`--text-md` 500)+상태(`--text-sm`, 강조 1개만 accent) | **Status 5개** | 상태 강조 2개 이상 금지 |
| **스트립** (섹션 축소형, 패딩 `--section-y/2`) | 소제목(`--text-xs` 600)+인라인 나열+설명 1문장 | **기술 스택 1회** | 배지 박스로 복귀 금지(G6) — 인라인 텍스트 나열이 확정 형태 |
| **히어로** | 텍스트 한 줄(사실 나열)→헤드라인→subcopy(2문장 이내)→CTA 2개(좌측 정렬로 꺾음) | 페이지 상단 1회 | pill 배지, CTA 라벨에 버전 포함 금지 |
| **푸터** | 상단 1px 보더, 링크 4개+저작권(`--text-xs`) | 페이지 하단 1회 | margin-top 중첩 금지(`--section-y` 리듬 유지) |

- 공통 섹션 골격(`.section-container`/`.section-title`/`.section-lead`)의 단일 정의는 `index.css`에만 둔다. 컴포넌트 CSS에서 재정의하는 것은 좌측 정렬 상쇄(G5) 같은 의도 있는 오버라이드에 한한다.
- 비인터랙티브 요소에 hover 피드백 금지(현재 `.card:hover` 제거 완료 — 재도입 금지).

## 4. 카피 규칙

### 4.1 독자 언어
- 독자는 "폰에서 PC 화면을 보고 싶은 사람"이다. 프로토콜 문서의 독자가 아니다.
- **판정법**: 문장을 소리 내어 읽었을 때 대상 사용자가 고개를 끄덕일 수 없으면(사양 나열, 안전 장비 목록 읊기) 그 문장은 랜딩에서 빼고 docs(README/`docs/`)로 보낸다.
- 예: 보안 s3의 알고리즘 나열(Ed25519, ChaCha20-Poly1305)은 랜딩에서 빼고 "첫 연결은 QR 코드로 서로 확인하고, 그 뒤의 화면·입력 데이터는 모두 암호화해 주고받습니다."로 풀어 쓴다. **단, "암호화한다"는 단정 수준은 유지** — SECURITY 리뷰 판정 존중.

### 4.2 종결·길이 편차
- "합니다" 종결이 전체 문장의 70%를 넘지 않도록 편차를 만든다.
- 섞는 수법: 체언 종결 1개(예: featuresLead "PC 화면을 폰에서, 여러 개로."), 짧은 단문(security lead "화면은 민감합니다."), 상황 서술형 첫 문장(hero subcopy — "~뷰어입니다" 정의형 개시 회피).
- hero subcopy 교체 시 정보 손실 대조 필수(다중 창·로컬 직접 연결·승인 기기 전송 보존).

### 4.3 금지 표현
- 과장 마케팅 표현 금지: "엔드투엔드", "제로 트러스트", "완벽한", "최고의" 등 검증 불가능한 강도의 수식.
- 구현 디테일의 나열(전송률 배수, 데이터 경로 내부 구조 등)은 docs 참조로 대체하거나 "왜"를 붙인다.
- 정보는 손실 없이 축소한다 — 기능 4·보안 4·스택 5·상태 5·링크 4의 사실은 유지.

### 4.4 "Rustra" 표기 — 유지 확정 (의도된 내부 도구명)
- "Rustra는"은 **오타가 아니다.** Rustra는 Leftcar가 Rust와 TypeScript 사이의 명령·상태·오류 계약을 관리하는 내부 계약/관리 도구의 이름이며, 언급을 유지한다.
- 단, 방문자 입장에서 이름이 뜻밖으로 보이므로 **문장은 Rustra의 역할이 드러나게 재작성**한다. 방향: "명령·상태·오류의 경계는 Rustra가 관리하는 계약(Rust↔TypeScript)으로 정의하고, 제품 로직은 TypeScript와 Rust로 작성합니다." 수준 — 이름이 살고, 역할이 설명되는 문장으로 site.ts의 stack.description에 반영한다.
- 이후 작업에서 "Rustra"를 제거하거나 다른 단어로 치환하지 않는다. 용어가 낯설다면 역할 설명을 덧붙일 뿐이다.

### 4.5 기술 알고리즘명
- 알고리즘·프로토콜 명칭(Ed25519, ChaCha20-Poly1305 등)은 랜딩에 나열하지 않고 docs(https://github.com/loopy-lim/leftcar/blob/main/docs/README.md) 참조로 안내한다. 랜딩에는 결과(무엇이 사용자에게 보장되는가)만 쓴다.

### 4.6 문장부호
- 중간점(·)은 제목의 대응 나열("키보드·포인터")에만 허용. 배지·라벨·저작권 등에는 쉼표나 풀어 쓰기를 쓴다.
